# Day 8 Capstone Reflection

The most difficult concept in this course was designing a system that remains reliable when many users access the same resource simultaneously. I initially found it challenging to understand how race conditions occur and why checking whether a seat is available is not enough to prevent double-booking. I overcame this difficulty by studying database transactions, row-level locking, unique constraints, and atomic updates. Applying these concepts to TicketHub helped me understand how a database can coordinate competing requests while maintaining consistent records.

Based on the feedback from my earlier scaling assignment, I would improve my technical documentation by making every section complete, explaining architectural decisions clearly, and checking that all required diagrams and calculations are included. For this capstone, I have focused on completing the six-part design framework and connecting the traffic estimates to the architecture. I would also improve the design further by conducting realistic load tests, measuring database contention, and refining the waiting-room admission rate using actual performance results rather than assumptions.

Next, I plan to learn more about cloud deployment, automated testing, and distributed systems. I want to gain practical experience deploying applications with Docker and a cloud platform, setting up continuous integration and delivery, and monitoring production services. I would also like to explore payment integration and message queues in greater depth. These skills will help me move from producing system-design documents to building, testing, deploying, and maintaining reliable applications that solve real-world problems.
